# Verify Docker workload images before replay

The default reviewer path may prepare images by tag. For a controlled replay,
use an explicit lock captured from the images you intend to evaluate:

```bash
PYTHONPATH=src .venv/bin/python scripts/docker_image_lock.py capture \
  --campaign 0.c0017 --campaign 0.shadowray --output /tmp/autosut-images.json
PYTHONPATH=src .venv/bin/python scripts/docker_image_lock.py verify \
  --campaign 0.c0017 --campaign 0.shadowray --lock /tmp/autosut-images.json
bash artifact/run.sh --image-lock /tmp/autosut-images.json
```

Capture records observations; it does not attest that an image is trusted or
scientifically appropriate. Keep the reviewed lock with your experiment inputs.
The capture and verify commands inspect images without building, pulling, creating containers or
changing tags. An undeclared image, missing image, changed ID, incompatible
platform or missing expected repository digest refuses verification.

In locked mode, all declared SUT and attacker images are checked before workload
provisioning, then each launch uses the verified image ID. No image pull or build
is attempted by these Docker workload launchers. The CLI loads one validated
lock for the invocation, so replacing the file mid-run cannot change its policy.
The bundle's image-contract.json binds the normalized lock and observations.
The original unqualified reference remains available in setup logs alongside
the resolved image ID. Single-campaign use is also supported:

```bash
PYTHONPATH=src .venv/bin/python scripts/run_orchestrated_campaign.py \
  0.c0017 --docker-image-lock /tmp/autosut-images.json
```

AUTOSUT_DOCKER_IMAGE_LOCK configures the same contract for direct Python callers.
It is optional. AUTOSUT_DOCKER_PLATFORM and DOCKER_DEFAULT_PLATFORM must agree
with the locked operating system, architecture and declared variant.

## Move the same images to another machine

A local image ID is not an image distribution mechanism. Export the reviewed
images by their verified IDs using the same lock:

```bash
PYTHONPATH=src .venv/bin/python scripts/docker_image_lock.py export \
  --campaign 0.c0017 --campaign 0.shadowray --lock /tmp/autosut-images.json \
  --output /tmp/autosut-workloads.tar
cd /tmp
shasum -a 256 autosut-workloads.tar > autosut-workloads.tar.sha256
```

Keep the printed archive digest and reviewed lock through your trusted transfer
channel. Transfer the archive, checksum and lock. Before loading on the
recipient's machine:

```bash
shasum -a 256 -c autosut-workloads.tar.sha256
docker image load --input autosut-workloads.tar
```

Then run the verify command above with that original lock. Do not capture a new
lock on the destination to make a mismatch disappear. A checksum detects changed
bytes relative to the expected digest; it does not authenticate the distributor.

The exporter checks identities before and after saving, saves by image IDs,
and retains requested names and original repository-digest aliases in the OCI
archive index. A raw `docker image save` of a digest-only reference can omit its name; loading that
archive may leave the reference unresolved. The exporter preserves image blobs
and their digests while adding the requested names. It refuses existing output
paths, changed identities, corrupt root descriptors and archive formats whose
root descriptors do not preserve the locked IDs, or repository digests that name
a different OCI root. Temporary files are cleaned
on failure and an incomplete archive is not published at the requested path.

This path requires a Docker OCI image store whose exported descriptor digests
match the locked local IDs. It is not a conversion between legacy config-based
image IDs and manifest-based IDs. Check recipient platform compatibility before
replay. No registry pull or image rebuild is performed by export or verification.
A successful image handoff still leaves runtime dependencies and campaign
qualification as separate checks.

## Scope

This contract covers Docker SUT/attacker image identity and platform, including
multi-host image references. It does not freeze packages installed after boot,
the CALDERA service lifecycle, external services, VM base images, or host tools.
The artifact's dependency, readiness, effect and teardown checks remain separate.
A passing image check does not certify campaign success or historical fidelity.
No default image is replaced and no submitted evidence is regenerated by capture.
