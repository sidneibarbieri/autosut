Reviewer Path

Claim under audit: structured CTI constrains executable SUT environments but does not uniquely determine them. This page is organized around the checks a reviewer is likely to run: rederive the measurements, inspect the claim-to-evidence map, and reproduce at least one executable witness.

Environment gap 139 SUT elements: 2.2% corpus-supported, 3.6% externally anchored, 15.8% AutoSUT-concretized, 78.4% analyst-authored.
Distinct reference roles CVE-2021-41773 is a decoy-variation harness check, not a material non-uniqueness witness. Internal SSH and HTTP examples vary service implementations under declared invariants.
Bounded operational witnesses 3 ledger claims are supported only within their stated witness scope; no card reports a campaign-wide execution rate.

Environment reconstruction boundary: what CTI fixes and what must be reconstructed

Why non-uniqueness exists: structured CTI fixes only part of the executable environment; the rest must be reconstructed. Every concrete SUT element is tagged by where it came from, then rolled up into a dimension × source table: the fixed (corpus) vs free (reconstructed) partition that the non-uniqueness result exploits. Computed deterministically from shipped provenance annotations; no live campaign run is required.

Of the 139 concrete SUT elements materialized across 20 campaign SUT profiles, 2.2% is anchored in the evaluated CTI corpus, 3.6% is anchored in external advisories or package metadata, 15.8% is an AutoSUT concretization of an under-specified corpus signal, and 78.4% is an explicit analyst lab choice the corpus does not constrain.
